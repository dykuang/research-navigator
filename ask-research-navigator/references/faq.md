# 常见问题与精确回答依据

**它和 ask-matt 有什么关系？**
参照 ask-matt 的“从意图选择技能/流程”设计。不是 Matt Pocock 的官方 Skill；本入口负责 Research Navigator 使用指导。

**它能直接帮我做科研吗？**
本入口解释和路由。真正的研究记录、状态更新、HTML 生成由同级 `research-navigator` Skill 执行。明确要求开始执行时切换。

**每次都要从选题开始吗？**
不用。五模块共享状态，可从文献、实验、Pivot 或总结开始；有既有项目先读状态和已有材料。

**科研论文会自动核实吗？**
当前 v0.2 没有自动学术真实性验真引擎或实验自动执行器。来源分级和验证提醒不等于真实性证明。

**为什么需要人类确认？**
事实、假设、行动、审批各自独立。用户可以批准研究行动，但不应把批准当作实验已证明。

**什么情况下会修改项目文件？**
帮助问答默认不写。主 Skill 执行具体操作时需要找到项目目录并遵守写入与审批边界。

**我的实验失败了，会被自动删除吗？**
不会。负结果须记录原因与范围，不会自动等于隔离/退休；归档保留证据、理由与回收条件。

**我想参考已搁置的想法？**
默认只读档案探索；用户确认复审和正式恢复是另外的步骤。恢复会产生新待验证候选，不覆盖旧结论。

**能在网页里直接点“批准”吗？**
独立离线 HTML 仍是只读快照。连接本机安全 Bridge 后可通过画布 **预览并提交待审批提案**；但不能在浏览器直接批准，必须在交互终端确认后刷新状态。

**Archify 是否已经支持？**
现有版本使用原生 SVG 依赖图，未启用 Archify 后端。不能把尚未实现的能力说成已支持。

**刚安装，Skill 找不到？**
确认 `ask-research-navigator/SKILL.md` 与 `research-navigator/SKILL.md` 位于该 Agent 的 Skills 根目录下，并重启或刷新可发现技能的会话。不同客户端安装机制不同；无法从远程会话保证本机已安装成功。

**可以在 Canvas 中管理 Agent 对话吗？**
可以按真实 SessionRef ID、角色和 Workspace 关联研究节点、复制 ID；v0.2 不会读取完整聊天正文，也没有经过验证的 Codex/ChatGPT 自动跳转深链接。不能把输入的 HTTPS 字符串当作已验证 provider deeplink。

**失败思路可以双击恢复吗？**
不行。只读参考不意味着批准。搁置要记录失败范围；回收需要分开批准复审和新候选创建，保留原负结果与归档历史。批准不等于验证科学结论。

**Windows 已自动安装了吗？**
没有。GitHub CI 可以在原生 Windows runner 上验证 Python/HTML 兼容性，但用户自己的 Codex/Windows 安装与会话定位仍必须手动检查。建议 PowerShell 中设置 `$env:PYTHONUTF8='1'`。
