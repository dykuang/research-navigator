## Intent

Turn v0.2 Research Canvas into a traceable **scientific reasoning graph**, distinguishing
research protocols, experiment attempts, observed results, evidence scopes,
researcher decisions and their original historical events. It must be possible to
follow the path `Hypothesis → Experiment → Run → Result → Claim → DecisionTrace`
without inventing transcript, experiment execution or scientific validity.

## Canonical data choices

Two new `items` entity types `ExperimentRun` (ID `RUN-XXXX`) and
`DecisionTrace` (ID `TRACE-XXXX`) live in existing
`research/state/items.json`, using the **same** journaling, file locking,
optimistic project revision and human-review state fields as v0.2. Additional
`run` / `decision_trace` metadata is optional on older projects;
do not create a shadow database or rewrite existing results.

### Run provenance

`ExperimentRun.run` stores: Experiment ID, numbered attempt, status
(`planned`, `recorded`, `invalidated`; `running` reserved for future adapters),
dataset identifier, protocol, code revision, seed, start/end ISO timestamps,
explicit metrics with unit/direction, synthetic-fixture flag, project-local
artifact path and SHA-256, and linked `Result` entity. The CLI **checks the
actual local file and hashes it** before it may record a run. A registered plan
is not execution evidence. Missing or out-of-project artifacts are rejected.
Malformed metrics, missing Result, mismatched artifact or duplicate attempts
are rejected by the state validator.

The new `Result` remains separate and can have positive, negative, mixed or
inconclusive outcomes. Recording a Run **does not** promote its epistemic status,
approve it for scientific use, or revise a research hypothesis automatically.
Invalidation retains the negative result and its history while propagating
`blocked` to dependent claims; unrelated shared Baselines remain usable.

### Scoped evidence

Existing v0.2 `evidence_links` retain explicit `stance`, `scope`, quality,
locator and source reference. `claim-analyze` produces an **advisory**
report: contradictory support flags a **possible** conflict with source
conditions to compare, never a proof of error. Evidence from invalidated/blocked
Result items is flagged. Review and epistemic promotion remain manual.

### Decision provenance

`DecisionTrace.decision_trace` refers to an existing `Decision` item, options,
selected option, rationale, specific evidence/Run IDs, actual append-only event
IDs and optional SessionRef IDs. It can link to human-attributed prior approval
events when present; `--actor user` is still a *declaration*, not authentication.
The trace remains `needs-user-confirmation` until reviewed.

`trace-replay` returns only **existing recorded events** (with actual timestamps)
and SessionRef IDs/workspace/provider. It does **not** synthesize an LLM
conversation, inspect full transcript, reconstruct vanished messages or guess
Codex deep links. No fake missing historical steps are filled in.

### Canvas

`graph_projection.project_graph(view="reasoning")` exposes typed nodes and
read-only provenance edges. The existing infinite Canvas supports a
**科学推理 / Reasoning** filter with Run and DecisionTrace inspector data;
semantic edits still use the protected v0.2 terminal-approved local proposal
bridge. The v0.3 registry/trace API is CLI-only until a future dedicated
proposal operation can enforce equivalent permissions.

## Verification / release gates

- Linux Python 3.10/3.12 and Windows Python 3.12 unit suites, including v0.1
  and v0.2 regression.
- Stable graph pagination, Canvas Chromium smoke tests, no uncontrolled browser
  writeback. No real citations or experimental results in fixtures.
- Manual owner Windows/Codex Skill discovery and actual SessionRef navigation
  remain **external checks**. Do not claim simulated CI proves real-client support.
- Native GitHub Milestone is distinct from a project's scientific Milestone.
- User approval required for merging, tagging and declaring stable release.
