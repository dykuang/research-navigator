# v0.4 Research Decision Intelligence · 契约与局限

这是 **只读、可审计、确定性** 的研究决策导航层；它读取 v0.3 的规范 JSON/事件记录，而不是调用 LLM 默默修改状态。其任务是帮助学生知道哪些证据还缺、下一项小实验可能区分哪些解释、哪些科学 Milestone 仍需验收。

## 命令

| 命令 | 输出 | 会写项目状态吗？ |
|---|---|---|
| `v04_project.py ROOT gaps` | 证据/依赖/人审缺口 | 否 |
| `v04_project.py ROOT opportunities` | 假设性最低成本区分检查 | 否 |
| `v04_project.py ROOT archive` | 归档复审清单 | 否 |
| `v04_project.py ROOT brief` | 导师决策 JSON | 否 |
| `v04_project.py ROOT brief --format markdown --output REPORT.md` | 导师摘要 Markdown 派生文件 | 只写用户指定报告文件，不改规范状态 |

输出含稳定的对象 ID 和对应缺口代码，可以进入相关 `ResearchBranch`、`Experiment`、`Milestone`、`Claim` 等记录。不可将 `OPP-0001` 之类报告内局部编号当作稳定持久研究实体 ID；每次报告可重新排序。

## 信息分层

1. **记录事实**：项目实体、来源、实验运行记录、已有关系、记录的影响/审核状态等，全部保留原 ID。
2. **程序可判定的缺口**：例如假设未连接 `tests` 实验、实验没有登记过实际 `ExperimentRun`、Claim 缺少有效证据链、科学里程碑没有相应验收证据、上游已标记需审查。这些不是科学真假的判定。
3. **待讨论的检查草案**：映射缺口到问题、预期区分观察和最小检查建议，强制标记 `execution_approved=false` 和 `human_review_required=true`。
4. **人类科研决策**：通过已存在的显式审批工作流提交；决策过程中的科学解释需要人工判断，不能从 CLI 的 `--actor` 声明推导真实身份。

## 证据和实验护栏

- 一份文献支持一项 Claim 不证明它对所有条件有效；反对与支持同时出现时只提示用户核对适用范围，不直接宣布矛盾或平均结果。
- 实验 `planned` 与 `recorded` 分离。Run 的日志哈希不等于科学结果真实或可重复。
- `negative` / `inconclusive` 记录并不自动 `quarantined`。如果检索发现失败历史，只能用于风险规避或用户授权的回收灵感。
- `archived` 方法即使满足用户描述的复审条件，也不会进入正向推荐。清单里的 `trigger_verified=false` 表示尚未验证。
- 成本与信息价值没有计算真实概率模型：成本默认 `unknown`，信息价值默认 `uncertain`，需要研究者结合领域资源评估。
- 报告只读，但输出落盘的 Markdown 和 HTML 需要考虑科研数据隐私；默认本机文件，不会向外部服务器上传。

## HTML 工作台

`build_dashboard.py` 仍提供经典 Dashboard 和无限画布；生成画布时额外创建 `research/canvas/decisions.html`。它是自包含的离线页面，含证据缺口筛选、建议审查、科学验收和归档提示，不包含任何能够直接修改实验/科研状态的按钮。服务端浏览器交互仍通过旧的本机 Bridge 人审提案流程，当前 v0.4 不新增直接审批 API。

## 已知局限

- 不是端到端 LLM 科研决策质量证明。规则提取的是已登记的状态，不会自动发现真实世界中尚未导入的论文或实验。
- 不推断任何潜在统计因果性、主张间真正逻辑蕴涵或可信概率；图中缺少一条关系并不一定说明科学上没有实验，只说明当前记录没有关联。
- 不替代导师对实验费用、研究方向、伦理或数据访问的审批。
- 长期自动持续监控新论文/资源变化尚未实现；archive watchlist 展示已记录条件，不主动抓取外部资讯。
- CLI 上的建议为候选文本，不是规范的任务实体。要执行应先由 Agent/研究者通过已有受控流程提案和审批。
