# M4 · 想法路线调整 (Diagnosis, Pivot & Revival)

**Entry**: weak, negative, inconclusive, incompatible or contradictory result; a newly found predecessor; changed resource conditions; user request to park or revisit. **Exit**: an auditable choice (continue, narrow, test, pivot, park, quarantine, retire, or review) with changed dependencies and concrete next discriminating action.

**Frontier interview**: what was actually observed and where recorded; implementation bugs vs scientific failure; sampling, metric and run quality; what exactly failed (conditions, datasets, parameters); which alternatives solve root cause and with what cost; user-approved next direction. The Agent should explicitly recommend a reversible low-cost diagnostic when uncertainty is high.

**Agent investigates**: logs/protocols and relevant errors, effect size with uncertainty, counterexamples, known sources; impacted downstream items and claims. Include the possibility that a negative experiment is inconclusive and no full pivot is justified.

**Human decisions**: alter core question, discard/park/quarantine/retire, authorize experiment budget, formally reopen archived work, approve new candidate. User saying "borrow a part of archived IDEA-0001" only permits read-only archive exploration. Revival requires separate explicit approvals; create new candidate ID, preserve old archived history.

**Artifacts**: `research/04-iterations/failure-analysis.md` (assumption, observation, diagnosis, confidence, scope, cost, possible cheap test), `pivot-log.md` (alternatives/trade-offs and choice), `revival-reviews/<id>.md` only when a review starts, plus archive card generated by dashboard engine.

**Rollback/links**: upstream novelty/data issues return to M1/M2; changed method marks M3 protocols and M5 claims stale. Do not delete methods, fabricate stronger statistical conclusions, or infer `quarantined` from any single negative run. See `../idea-lifecycle.md`.
